观测通道：日志分类

日志共 12 个分类，导出后按分类名搜索即可定位：
app capture session route interrupt thermal disk storage system asr model translate

排错时最常用的四个：capture（采集与分片）、asr（转写耗时与实时倍率）、storage（清理与写入）、translate（语言可用性与批量翻译）。

1. M1 录音内核 硬闸门

为什么单独强调：「全时 + 锁屏 + 不断档」是本项目唯一的高风险项，且一旦不成立，后面所有功能都没有意义（设计文档 13 章）。这一节必须真机实测，不能只看日志。
✓编号操作期望不通过时说明什么
M1-1 前台连续录 8 小时（插电，可放着不看） 录音持续；会话详情时长约 8 小时；分片按 60 秒一个连续排布 进程被杀 / 录音自行停止 → 最高优先级问题，记下停止时刻与日志 capture + thermal 段
M1-2 锁屏 8 小时（同上，中途锁屏不打开） 锁屏期间仍在录；解锁后时长继续增长 锁屏即停 → 保活失败。这是本项目最致命的一类失败，请把 session/interrupt 日志发我
M1-3 录制中来一通电话 / 打开音乐播放器 / 拔插耳机各试一次 日志出现 interrupt 或 route 记录；中断结束后自动恢复录音 不恢复 → 中断恢复逻辑失效；恢复后无音频 → 引擎未真正重建
M1-4 查看上述被中断的那次会话详情 断口被如实标出（有多少秒没录上） 看不到断口 → 时间轴在假装连续。这比"有断口"更糟，因为它让用户以为录全了
M1-5 自检页「音频事件监听」：查看「已收到事件数」 做过 M1-3 之后该数字应 > 0 始终为 0 → 四类沉默事件的监听根本没接上（它们不报错，只能靠这个数字确认）
M1-6 录制中把音量调到很低/对着麦克风静音 5 分钟，再恢复说话 恢复后音频与转写正常；未出现整段丢帧 出现爆音或丢帧 → 实时音频线程里做了重活（设计文档 R30，属数据静默损坏）

2. M2 转写

✓编号操作期望不通过时说明什么
M2-1 自检页「离线引擎」→ 看 whisper 后端 一行 硬闸门 显示一段非空的后端信息（如 CPU/NEON 等） 「不可用」→ whisper.cpp 的空壳或未链接。这是 M2a 的硬证据，比"编译通过"强得多
M2-2 开始录音，对着手机连续说话 1 分钟 录音页出现实时字幕；句子会先出现、后被打字修正，最新一句带「识别中」标记 完全不出字 → 实时字幕未启动（看界面是否提示模型未下载）；文字跳动是设计行为不是故障
M2-3 停止录音 → 记录 → 打开会话 → 点「转写为文字」 显示进度（已处理 N/M 分片），完成后出现文字稿 失败时界面会给出原因（模型未下载 / 无音频）；已转部分会保留，可继续
M2-4 在会话详情里切换实时稿 / 终稿 终稿质量明显优于实时稿（错字更少、标点更合理） 两者一样 → 终稿可能实际用的是同一个模型（检查设置里的「终稿模型」是否为 small）
M2-5 导出日志，搜 asr 分类里的「实时倍率」 终稿倍率（耗时 ÷ 音频时长）有明确数值 这一项是整个项目最需要数据的地方：倍率 > 1 表示慢于实时，直接决定实时字幕是否可行、以及 base/small 的选型是否要改
M2-6 录音时静音 2 分钟（不说话） 实时字幕不出字或明显收敛 冒出一堆通顺但与实际无关的句子 → 静音幻觉（能量门限未拦住）

3. M3 语音处理（VAD / 降噪 / 说话人分离）

✓编号操作期望不通过时说明什么
M3-1 自检页看 sherpa-onnx 一行 显示非空版本号 «不可用» → sherpa 静态库未真正链接
M3-2 两人交替说话的会话，转写后看会话详情 句子带说话人编号与颜色；同一人前后基本一致 编号乱跳 → 声纹阈值需标定（P4 / 风险 R5）。宁可不合并也不要误合并是刻意取向
M3-3 给某个说话人命名 → 另录一段他说话 → 看新会话 新会话自动认出该名字（声纹库命中） 认不出 → 声纹库未写入或阈值过严；自检页「声纹库」应显示已录入人数
M3-4 对同一段音频，分别看终稿与降噪稿（同一模型，唯一差别是过了降噪） 能人工判断出降噪是帮忙还是帮倒忙 这是设计文档要求的"可验证选项"：若降噪反噬识别率，就把默认值改成关闭（风险 R7）

4. M4 存储与检索

✓编号操作期望不通过时说明什么
M4-1 记录页搜索框输入一个几周前说过的词 搜到该句，并显示来自哪次会话 / 哪一稿 搜不到 → 索引未建或未随转写更新；自检页「检索索引」会显示能力状态
M4-2 点搜索结果 / 点任意一句 → 听 从该句起点播放、到该句终点停止（不是播完整个分片） 播放位置偏 → 时间轴映射有偏差（这类问题在真机上只会表现为"播放器不好用"）
M4-3 播放时点倍率（0.5 / 0.75 / 1.0），开单句循环 慢放不变调（音高保持）；循环在单句内重复 变调说明用了简单降速而不是时间伸缩 —— 那反而更听不懂
M4-4 把保留期改短（如 3 天），等待清理（或找一条超期会话） 音频被清理，但文字稿仍在 文字也一起没了 → 违背"文本永久、音频有限"的设计（9.4）

5. M5 翻译

✓编号操作期望不通过时说明什么
M5-1 会话详情选源语言与目标语言；观察语言列表 列表按可用性分组（已就绪 / 需下载 / 不支持），不可用的明确标出 选完才发现不能用 → 违背"必须前置校验"（R17 / 7.4）。不可用必须提示，不得静默失败
M5-2 点翻译 → 出译文；切到别的语言再切回来 首次批量翻译有进度；已翻的语言秒出（走缓存） 不秒出 → 缓存未命中（看日志 translate 分类）
M5-3 手动改一句译文 → 再点一次翻译（重跑） 手改的那句保持不动，不被自动译文覆盖 被覆盖 → 会抹掉用户的手改成果，属最恼人的一类 bug（已在 M5 专门处理）
M5-4 用译文里的词去搜索 能搜到，且命中行标注"某语言译文" 不标注 → 用户会以为自己录音里真的说了那句译文
M5-5 拿一段真实口语（含俚语/长难句/专有名词）看译文 记录下明显失真的类型与例子 端侧翻译必然有失真（R16）。需要的是样本与类型，而不是"好不好"的判断 —— 这决定要不要评估引入本地小 LLM

6. M6 语言学习

✓编号操作期望不通过时说明什么
M6-1 打开一段有文字稿的会话，看每句下方 出现蓝色生词 chips（每句最多 4 个 + 「+N」） 一个都没有 → 可能是词表未打包或学习语言无词表；界面会给出说明，不会静默
M6-2 设置 → 学习 → 把水平档从 A1 改成 C2，再回会话看 本次新增 生词数量应明显减少（A1 标得多、C2 几乎只标词表外的词） 两者没差别 → 水平档没接进判定（那就等于开关是假的）
M6-3 点一个蓝色 chip 变成绿色；切到「生词本」标签能看到它，并带来源原句 看不到 → 生词本写入失败（看日志 storage）
M6-4 在句子行上左滑 → 跟读 → 录一遍 → 停止并评测 给出得分与逐词对照（绿=读对 / 红=没听到 / 橙=读成别的词），并显示"模型听到的是" 录音无声 → 界面会当场提示"几乎没有声音"（不是等你录完才说）；它测的是"读对了没有"，不是发音评分
M6-5 会话详情 →「学习模式」 本次新增 整屏进入逐句卡片；复读原声是最醒目的大按钮；可切上一句/下一句 进不去 → 需要先有文字稿（界面会说明"请先转写为文字"）
M6-6 学习模式里点「朗读」→ 读原文 / 读译文 / 连播全部译文 本次新增 三档都能出声；语速偏慢（刻意）；右上角可隐藏原文/译文做盲听 完全不出声且提示缺语音包 → 到 设置 → 辅助功能 → 朗读内容 → 声音 下载该语言语音。系统找不到语音时会用默认语音照读，所以这里刻意改成显式报错
M6-7 学习模式 → 右上角书本图标 → 本会话生词列表 → 点一个词 跳到该词所在的句子 点了没跳 → 若当时开着「只看有生词」筛选，代码会自动关掉筛选后再跳；仍不跳请记下
M6-8 生词本页 → 右上角分享按钮 本次新增 可选择「表格（Anki 导入用）」与「Markdown」两个文件 按钮不存在 → 设置 → 学习 →「允许导出」被关了（这是开关的正确行为）
M6-9 把导出的表格导入 Anki（导入文件 → 选该 .csv） 能正常导入；列顺序为 词形 / 难度 / 备注 / 来源句 / 来源 出现一张内容为表头的脏卡片 → 说明首行被当成数据了（本实现刻意不带表头，若发生请告诉我）
M6-10 会话详情 →「导出文字稿」（在「学习模式」同一行） 本次新增 导出 Markdown；若该次录音有断口，文件开头写明断口处数与秒数 没写断口 → 拿到留档的人会以为录全了
M6-11 设置 → 学习 → 学习语言切到中文，看一段中文会话的生词 中文能分词并标出生词（不再是"不支持"） 报"词表未就绪" → 中文词表未打包；报"不支持"→ 说明语言识别没走到中文
M6-12 走一遍完整闭环：听（复读）— 看（卡片）— 复读（慢速/循环）— 收词（点 chip） 全程不跳页、不弹窗遮挡，一屏内完成 这是 M6 的验收标准本身（R22：交互成本过高 = 做了等于没做）。哪里卡手最值得反馈

7. 已知边界（不算缺陷，不用报）

下列都是设计上明确不做或尚未实现的，看到它们出现属预期；反过来，如果它们"看起来能用了"，才需要告诉我。
现象原因 / 状态
学习模式里没有「只看目标语言的句子」依赖 7.5 逐段语言检测，该能力尚未实现。刻意不做假开关（附录 B.9）
导出表格的「释义」列是空的端侧生成释义（Foundation Models）尚未实现，不做假占位
生词判定只支持英语与中文只备了这两份词表；选到别的语言会关闭判定并提示，不会乱标
跟读比对不给"发音分数"whisper 只能回答"读对了没有"。把 think 读成 sink 会被判错，但舌位略偏仍会判对（R21）
生词本没有复习计划 / 记忆曲线v1 明确不做 SRS（8.7），只做生词本 + 手动标记已掌握
译文里偶有失真端侧翻译的固有限制（R16）；原文始终显示在译文上方
录音里偶尔混入手机外放的声音默认「共存」会话模式的代价 —— 换来的是"一直能录"（R28）。会议模式（M8）天然绕开

8. 结果怎么回给我

最有用的是这三样，按价值排序：

  • 不通过的项 + 当时的日志导出（自检页 →「查看日志 / 导出」→ 分享给我）。有日志我基本能直接定位。
  • M2-5 的实时倍率数值（日志 asr 分类「实时倍率」）。这是目前最缺的一项数据，它决定模型选型与实时字幕是否可行。
  • 主观感受：哪一步最卡手、哪句话你觉得标错了生词、哪句译文明显不对。这类反馈代码里看不出来，但直接决定要不要改。

整份清单不必一次做完。M1 的两条硬闸门（8 小时前台 / 8 小时锁屏）建议单独安排，插着电放着就行。
